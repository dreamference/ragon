Installer

$ curl -fsSL https://github.com/dreamference/ragon/releases/latest/download/install.sh | bash
$ ragon-admin server start      # télécharge le modèle une seule fois (~20 Go), puis le sert
$ cd ~/your-project && ragon    # c'est tout

Fonctionne sur le NVIDIA DGX Spark et sur toute machine GB10. Le script vérifie chaque téléchargement avec les sommes de contrôle de la version et affiche chaque commande sudo avant de l'exécuter. Lisez-le d'abord si vous le souhaitez.

Clients Mac et Linux

Vos autres ordinateurs utilisent le modèle du GB10 via le réseau local. Sur un Mac ou une autre machine Linux, la même commande ci-dessus installe le client ragon, qui trouve le GB10 tout seul.

Client Windows preview

> irm https://github.com/dreamference/ragon/releases/latest/download/install.ps1 | iex

Dans PowerShell. L'installation se fait sans droits d'administrateur, puis Windows demande une fois de configurer le bac à sable de l'agent. Pas encore signé : Smart App Control doit être désactivé. Lisez le script.

Autres façons d'installer

La page de la version propose aussi le dmg pour Mac (Ragon-<version>-arm64-preview.dmg, ou x64 pour Intel) et l'installeur Windows (Ragon-Setup-<version>-x64.exe, ou arm64). Ce sont des previews non signées : téléchargées dans un navigateur, elles sont bloquées la première fois. Vérifiez d'abord chacune avec le fichier SHA256SUMS signé de la version.

  • macOS 15 et plus récent : faites glisser Ragon dans Applications et ouvrez-la une fois, puis Réglages Système › Confidentialité et sécurité › Ouvrir quand même. Sous macOS 14 et antérieur, Control-clic sur l'application › Ouvrir.
  • Windows : SmartScreen › Informations complémentaires › Exécuter quand même. Smart App Control doit être désactivé.

À essayer d'abord

Ou mettez du travail en file pour cette nuit avec /night add <task> : Ragon déroule la file pendant que vous dormez, chaque tâche sur sa propre branche git, et vous relisez les branches en buvant votre café.

$ ragon "explain this repository to me like I'm new on the team"
# reads the code index (ragon-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ragon "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ragon-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Ce que vous obtenez

L'application de bureau de Ragon réunit Ask et Work dans une seule fenêtre. Work est un véritable établi pour les sessions d'agent : un compositeur avec fichiers, skills et commandes, un volet de revue pour indexer, annuler et valider, des worktrees, des onglets de terminal, ainsi qu'une arborescence et des onglets de fichiers à côté de la conversation. Sur vos autres ordinateurs, c'est un client de votre GB10, qu'elle trouve sur le réseau local.

Votre code ne quitte pas votre bureau — et vous pouvez le prouver

Les agents de programmation dans le cloud envoient votre code source sur les serveurs d'un tiers. Ragon ne l'envoie nulle part : le modèle tourne sur votre GB10, et rien dans Ragon ne contacte l'extérieur. Pas de statistiques d'usage, pas de métriques, pas de connexion, pas de rapports de plantage « anonymes ». Il devient ainsi utilisable pour du code que vous n'avez pas le droit d'envoyer : travail pour des clients, données réglementées, produits non sortis.

Une commande lance une vraie session Ragon sous strace et liste chaque connexion réseau qu'elle a établie :

$ ragon-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Tout est resté sur 127.0.0.1. Pas une seule requête DNS.

Besoin d'une garantie ferme ?

Tapez /airgapped on et chaque commande que l'agent exécute reçoit du noyau Linux un espace de noms réseau vide. Ce n'est pas une demande polie faite au modèle : il n'y a tout simplement aucun réseau à atteindre. Full Access, qui contournerait le bac à sable, est refusé en même temps.

Ce qui peut sortir, et quand

Seulement ce que vous ou l'agent demandez : une recherche web (via un SearXNG privé sur votre propre machine), le téléchargement d'une page, une requête en lecture seule vers un compte Google que vous avez connecté, ou une vérification de mise à jour. Avec /airgapped on, rien de tout cela.

FAQ

Ai-je besoin d'un GB10 ?

Oui, pour faire tourner le modèle. Vos autres ordinateurs l'utilisent comme clients : Linux (Arm ou x86) et macOS avec la même commande d'installation, Windows (Arm ou x86, preview) avec la ligne PowerShell.

Est-ce vraiment gratuit ?

Oui. Ragon est open source sous licence AGPL, et les poids du modèle sont libres. Votre seul coût de fonctionnement est l'électricité.

De quoi ai-je besoin en plus de la machine ?

Du système livré avec elle (DGX OS 7, ou Ubuntu 24.04 là où le constructeur le propose), de Docker avec le NVIDIA Container Toolkit, de Python 3 et de Git. Sur un Ubuntu ordinaire, ragon-admin host check vous dit ce qui manque.

Quelque chose atteint-il jamais internet ?

Seulement ce que vous ou l'agent demandez, comme une recherche web via SearXNG sur votre propre machine, et les téléchargements du premier lancement. /airgapped on coupe tout cela.

Quel modèle fait-il tourner ?

Qwen3.8-27B au format NVFP4 4 bits de NVIDIA, servi par notre moteur ragon-serve avec un drafter DFlash2 (SGLang reste la solution de repli pendant toute la 0.9.x), choisi et réglé pour le GB10. Environ 20 Go de poids ; il reste environ 38 Go de mémoire libres sur la machine pendant le service.
