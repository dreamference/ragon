Instalar

$ curl -fsSL https://github.com/dreamference/ragon/releases/latest/download/install.sh | bash
$ ragon-admin server start      # descarga el modelo una sola vez (~20 GB) y lo pone en marcha
$ cd ~/your-project && ragon    # y ya está

Funciona en el NVIDIA DGX Spark y en cualquier máquina GB10. El script verifica cada descarga con las sumas de comprobación de la versión e imprime cada comando sudo antes de ejecutarlo. Léelo antes si quieres.

Clientes para Mac y Linux

Tus otros equipos usan el modelo del GB10 a través de la red local. En un Mac o en otra máquina Linux, el mismo comando de arriba instala el cliente ragon, que encuentra el GB10 por sí solo.

Cliente para Windows preview

> irm https://github.com/dreamference/ragon/releases/latest/download/install.ps1 | iex

En PowerShell. Se instala sin permisos de administrador y después Windows pide una vez configurar el sandbox del agente. Aún sin firmar, así que Smart App Control debe estar desactivado. Lee el script.

Otras formas de instalar

La página de la versión incluye además el dmg para Mac (Ragon-<version>-arm64-preview.dmg, o x64 para Intel) y el instalador de Windows (Ragon-Setup-<version>-x64.exe, o arm64). Son previews sin firmar: si los descargas con un navegador, se bloquean la primera vez. Comprueba cada uno con el archivo SHA256SUMS firmado de la versión antes de abrirlo.

  • macOS 15 y posterior: arrastra Ragon a Aplicaciones y ábrela una vez; luego Ajustes del Sistema › Privacidad y seguridad › Abrir igualmente. En macOS 14 y anteriores, Control-clic en la app › Abrir.
  • Windows: SmartScreen › Más información › Ejecutar de todas formas. Smart App Control debe estar desactivado.

Prueba esto primero

O deja trabajo en cola para esta noche con /night add <task>: Ragon recorre la cola mientras duermes, cada tarea en su propia rama de git, y revisas las ramas con el café.

$ ragon "explain this repository to me like I'm new on the team"
# reads the code index (ragon-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ragon "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ragon-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Qué obtienes

La app de escritorio de Ragon reúne Ask y Work en una sola ventana. Work es un banco de trabajo completo para sesiones de agente: un editor con archivos, skills y comandos, un panel de revisión para preparar, revertir y confirmar cambios, worktrees, pestañas de terminal y un árbol de archivos con pestañas de archivo junto al hilo. En tus otros equipos es un cliente de tu GB10, que encuentra en la red local.

Tu código no sale de tu escritorio, y puedes comprobarlo

Los agentes de programación en la nube envían tu código fuente a los servidores de otra empresa. Ragon no lo envía a ninguna parte: el modelo corre en tu GB10 y nada en Ragon contacta con el exterior. Sin analíticas de uso, sin métricas, sin inicio de sesión, sin informes de fallos «anónimos». Eso lo hace utilizable con código que no tienes permitido subir: trabajo de clientes, datos regulados, productos sin lanzar.

Un solo comando ejecuta una sesión real de Ragon bajo strace y lista cada conexión de red que hizo:

$ ragon-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Todo se quedó en 127.0.0.1. Ni una sola consulta DNS.

¿Necesitas una garantía firme?

Escribe /airgapped on y cada comando que ejecute el agente recibe del kernel de Linux un espacio de nombres de red vacío. No es una petición educada al modelo: simplemente no hay red a la que llegar. Full Access, que se saltaría el sandbox, se rechaza al mismo tiempo.

Qué puede salir, y cuándo

Solo lo que tú o el agente pidáis: una búsqueda web (a través de un SearXNG privado en tu propia máquina), la descarga de una página, una petición de solo lectura a una cuenta de Google que hayas conectado, o una comprobación de actualizaciones. Con /airgapped on, nada de eso.

FAQ

¿Necesito un GB10?

Sí, para ejecutar el modelo. Tus otros equipos lo usan como clientes: Linux (Arm o x86) y macOS con el mismo comando de instalación, y Windows (Arm o x86, preview) con la línea de PowerShell.

¿Es realmente gratis?

Sí. Ragon es de código abierto bajo la AGPL, y los pesos del modelo son gratuitos. Tu único coste de funcionamiento es la electricidad.

¿Qué necesito aparte de la máquina?

El sistema operativo con el que viene (DGX OS 7, o Ubuntu 24.04 donde el fabricante lo ofrece), Docker con el NVIDIA Container Toolkit, Python 3 y Git. En un Ubuntu normal, ragon-admin host check te dice qué falta.

¿Llega algo alguna vez a internet?

Solo lo que tú o el agente pidáis, como una búsqueda web a través de SearXNG en tu propia máquina, y las descargas de la primera vez. /airgapped on lo desactiva todo.

¿Qué modelo ejecuta?

Qwen3.8-27B en el formato NVFP4 de 4 bits de NVIDIA, servido por nuestro motor ragon-serve con un drafter DFlash2 (SGLang sigue como alternativa durante toda la 0.9.x), elegido y ajustado para el GB10. Unos 20 GB de pesos; mientras sirve, quedan libres unos 38 GB de la memoria de la máquina.
